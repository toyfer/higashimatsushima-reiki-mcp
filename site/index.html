東松島市例規 静的API

東松島市が公開している例規ページから GitHub Actions で生成した読み取り専用 JSON です。一次情報は東松島市公式サイトで確認してください。

エンドポイント

  • api/meta.json
  • api/health.json
  • api/laws/index.json
  • api/search/title-index.json
  • api/search/manifest.json
  • api/search/postings-{00..NN}.json
  • api/search/chunks-{000..NNN}.json
  • api/laws/{law_id}.json

シャード数は固定ではありません。実際の本数は api/search/manifest.json の posting_shards と、chunk_count ÷ chunk_shard_size から求めたチャンクシャード数で決まります。

例

GET /api/meta.json
GET /api/laws/index.json
GET /api/laws/r122RG00000002.json
GET /api/search/manifest.json

本文検索

api/search/manifest.json はビルド時に生成した bigram TF-IDF 索引の説明です。data_version は同じビルドで作られた postings と chunks の版を表すので、検索前に必ず照合してください。版が一致しない postings と chunks を組み合わせると、chunk 番号が別の条例を指します。

検索は2段階です。bigram の posting で候補を作り、その後に chunk の全文（chunk shard の text）で語句の連続一致を確認します。600点 と 500万円 を含む chunk は 600万円 の4つの bigram をすべて持ちますが、連続した文字列ではないため除外されます。bigram だけの一致を残す場合は exact=false を指定し、結果の match_type が approximate になります。

複数語の扱いは operator（AND/OR）と scope（chunk/law）で指定します。chunk は同一 chunk 内に全語が必要、law は同一条例内のどこかに各語があれば成立し、matches[] に語ごとの根拠 chunk が付きます。結果には snippet と highlights、matched_terms、unmatched_terms が入ります。

索引側は 1 term あたり最大 50 posting、1 条例・1 term あたり最大 3 posting、Worker 側は 1 回の呼び出しで最大 46 fetch・300 候補で打ち切ります。応答の completeness（complete/partial）と filtered_out_exact / filtered_out_no_term / skipped_per_law / index_caps で、語が無いのか上限に達したのかを区別してください。

日本語は 2 文字以上のクエリが必要です（索引が bigram のみのため、税 のような 1 文字は対象外）。

版の扱い

公開しているのは現在版のみです。各条例 JSON には content_current_date と data_version が入ります。過去時点の条文は提供しないため、日付指定の取得は未対応として明示的に拒否します。

MCP は Cloudflare Worker がこの静的 API をラップして提供します。ツールは reiki_status、search_laws_by_title、search_laws_by_content、get_law、get_article、get_toc、get_unit の 7 つです。
